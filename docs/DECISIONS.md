# Decisions and conflicts

- Phase 0 says four sample assets but enumerates five. Ship three videos, one audio, one image. Pexels/Pixabay are not assumed CC0. Deterministic original synthetic fixtures are generated locally with FFmpeg instead; no unverified external copyright claims.
- Missing nested contract fields receive minimal explicit schemas, documented in CONTRACTS.md.
- Initially no public preview was authorized. On 2026-10-26 the user explicitly authorized temporary frontend previews for browser testing and screenshots. Disposable previews expose only the frontend and synthetic mock routes with a clean environment and bounded lifetime. Local Playwright browsers remain prohibited; authored scripts are not execution evidence.
- Phase 1 numeric exceptions (10px padding,22px pill, animation timing) extend named CSS tokens; components never contain raw typography/colors/timings.
- Phases 5 through 10 were subsequently supplied. They are implemented sequentially; later-phase boundaries remain explicitly labelled until their implementation and checks occur.

- Generated CC0 mock media are excluded from Git and recreated by `postinstall` using FFmpeg. This avoids publishing approximately 24 MB of reproducible binary test data. The generator and provenance remain versioned; FFmpeg is a system prerequisite.
- Phase 1 extra named tokens: hairline 1px, stroke 1.5px, small icon 14px, pill 22px, inset 10px, attachment name 160px, dialogs 440/560px, toast 420px, kbd 18px, toggle 28x16px. Derived colors mix existing palette tokens only. Functional overlay/floating/toast layers are 40/50/60. Gallery max-width is 1200px. Operational tooltip and toast timings are centralized in ui/tokens.ts. These are implementation defaults, not newly inferred user preferences.
- `NEXT_PUBLIC_SITE_URL` sets metadataBase. Local development defaults to http://localhost:3000; no production hostname or deployment is invented.
- Test entry point forces NODE_ENV=test because this build machine defaults to production. This is necessary for React's test act API and does not weaken assertions or change production builds.
- Global upload browser listeners and toast provider live above routes, so navigating from the landing page to warm-up does not detach offline/resume notifications or cancel transfers.

## Source craft/accessibility review, 2026-10-26

The Phase 1 source review used web-design-guidelines and impeccable audit/craft-floor guidance. It found a default context-menu keyboard-reachability defect, a slider focus-ring cascade defect, and pointer-highlighted menu items incorrectly receiving a keyboard focus ring. All three corrections are implemented; the UI suite now passes 28 tests, including keyboard and CSS-intent regressions. This source review is not a rendered accessibility pass.

A specification conflict remains: the required cream-38 on ink-2 has approximately 3.31:1 contrast for placeholder text, and on ink-1 approximately 3.28:1 for inactive tabs. These source-token calculations are below the 4.5:1 normal-text target. The exact supplied palette is preserved rather than silently changing the design bible. Thus an unconditional WCAG/axe zero-issue acceptance is not asserted. A future explicit design decision would be needed to change these text colors.

Browser-storage denial must not turn an accepted session into a false creation failure. The draft store now retains the live session even if sessionStorage writes fail; malformed and inaccessible saved storage restore safely to null. Four regression tests pass.

The prescribed default development port 3000 is occupied by the environment's host application. The unmodified pnpm dev command correctly attempted 3000 and returned EADDRINUSE. An alternate-port invocation, pnpm --filter @kimo/web exec next dev -p 3100, became Ready and served the landing HTML with status 200 and data-ready=true. This is HTTP smoke evidence only, not browser rendering proof. The required project default stays 3000.

The actual pnpm mock and pnpm mock:demo commands succeeded. The CLI emitted 45 project.ops events with consecutive versions 1 through 45, 45 successful action completions, and the final ask_review message. No browser was used for this check.

- Phase 2 film grain is an original deterministic 160x160 grayscale PNG generated by scripts/grain.mjs using a fixed xorshift seed, Node zlib and PNG CRCs. No external asset or additional library is used; postinstall regenerates the exact tile.
- The unspecified aggregate upload-limit reason is `your files are over 5 GB in total`, following the specified validation sentence pattern. How-it-works cards use explicitly static icon still placeholders, not fabricated demo recordings.

- Pause/resume has no protocol acknowledgement. The pill exposes local dispatch intent, superseded by the next server state, rather than claiming backend acknowledgement.
- The Phase 5 keyboard map assigns L to both loop and shuttle. L takes the central-map shuttle action; loop remains a keyboard-reachable toggle.
- Future compositor, editing and agent-message operations are slots or explicitly labelled phase boundaries, not fake implementations.

## Bounded test-preview recovery

Repeated execution restarts destroyed local disposable-preview processes before full automatic navigation could be verified. A manually dispatched GitHub Actions preview is being added as a bounded synthetic test environment, not a production deployment. It uses read-only repository permissions, no provider/backend credentials, allowlisted mock routes, and an automatic shutdown. No local browser or Playwright execution is introduced.

`KIMO_API_INTERNAL_URL` optionally routes server-rendered requests to the same typed API over an internal service address; the browser continues using only `NEXT_PUBLIC_KIMO_API`. When unset, existing defaults are unchanged. This prevents a fresh public tunnel's DNS propagation from becoming an SSR dependency. No secrets are embedded or copied into browser configuration.

## Phase 7 integration choices, 2026-10-27

- The timeline editor owns one ruler, visible track canvases, minimap and assets drawer. The older shell ruler/footer are not rendered around this slot. Timeline zoom is real pixels/second in the specified 4 to 600 range; null selects fit.
- The four named LUT options have no supplied numerical transforms or engine preset IDs. Original deterministic sRGB 64-cube atlases are authored in `scripts/editor-luts.mjs` and checked byte-for-byte against shipped `/luts/*.png`. They are frontend creative looks, not replicas of undocumented engine presets. IDs use a `kimo-local-lut-` namespace and register as actual typed image assets. GPU sampling and backend resolution of these public resources remain acceptance boundaries.
- Upload more uses the existing upload queue, then a single existing messages request with attachment IDs and an empty text. It does not create a second session or synthesize an agent instruction. The mock validates completed uploads, deduplicates IDs and emits actual asset.added events. Production acceptance requires the existing engine to associate those attachments; the frontend explicitly reports an unconfirmed association rather than inventing it. An uncertain request is never replayed.
- The project-save indicator reads the transaction service state independently of the locally saved title. Unknown delivery or unavailable browser storage is not labeled saved.

- Editor copy/paste uses a session-only immutable clip snapshot and fresh clip/effect/link IDs, with paste positioned at the playhead and validated against current unlocked compatible tracks. It never overwrites the system clipboard. Timeline-local keyboard handlers consume their gestures before the single global handler, preventing duplicate batches.

- Timeline extraction is gated on actual preview readiness. Its handle identity stays stable across playhead updates, but changes with session, registry or readiness, so visible-cache entries are not discarded every playback frame or filled with pre-initialization empty results.
- Viewer text-handle drags reuse measured overlay geometry and the same editing transaction. Screen movement is divided by the actual display scale; rotation and scaling use the transformed anchor. Pure geometry and mocked lifecycle tests do not establish rendered typography or GPU fidelity. A 0.01 scale floor prevents invalid zero-scale operations.

- Replacement media uses actual registered sources or one confirmed upload in the existing session. Same-kind media are required. Placement and styling are retained, source time and duration are clamped to verified replacement headroom and whole-frame bounds, and source-specific masks are discarded atomically. Missing duration is an explicit boundary, not an invented length. Search mode currently filters already-registered web assets; it does not claim a new stock-search provider request.
- Locally probed upload duration and dimensions fill only missing frontend asset metadata after the server confirms attachment. They are not presented as server-persisted metadata, and a later server snapshot may correctly return unknown metadata.
- In-place viewer editing uses separate primary/secondary Pixi glyph bounds and actual resolved font metrics. Only a ready registered font can hide the canvas layer. Font-pending or failed metrics keep the preview visible and expose a read-only status. The editor remains inside the existing fullscreen surface.
- Inspector activity comes only from changed property leaves in operation packets correlated to a currently running action. Identical patches do not create activity; ending the action clears it. No action authorship is inferred from equal operation contents.
- Synthetic agent operations now reject a complete batch that touches locked clips or tracks, and report the actual action failure. This is mock-producer enforcement for deterministic frontend tests, not evidence of production-engine locking or permission agreement.

## Phase 9 review and delivery choices, 2026-10-27

- Review and approval share the Shell editor/socket. Acting confirmation uses the recorded action-group summary and waits for the synthetic producer's actual idle/paused status, not a local pause intent or claimed production acknowledgement.
- Actual top-bar title is lifted into the Shell, preserving local title storage and server-title fallback. Approval freezes that title and acknowledged revision. Draft/pending/unknown edits must resolve before approval; none are silently discarded.
- Approval performs at most one POST. Explicit rejection differs from uncertain network/server/schema delivery. A lost response is reconciled through an actual new recorded job identity, otherwise read-only recheck, never automatic re-approval.
- Poster acquisition reads the actual submitted composition from the existing Pixi renderer. It returns real preview dimensions/approximations and rejects retained, unavailable, tainted, font-pending, stale or aborted work. Source thumbnails never substitute. A transient Blob crosses the route; reload loses it honestly.
- Exact Phase 9 values use central semantic tokens. The named render sheen is the permitted render gradient; delivery uses a solid translucent band, not another gradient. Actual composed/render/delivery frames share kimo-viewer, with capability/reduced-motion fallback that never blocks routing.
- Failed-render retry reopens Studio with ?review=render, opening explicit review but never auto-approving. Cancel/reopen require server evidence. Failed sessions with actual render IDs restore that job; unrelated failures retain their error boundary.
- Public delivery never infers ownership from shared video IDs or browser storage. Edit-again needs verified owner capability. Missing ownership and known expiry are distinct boundaries.
- Synthetic output is a fixed original eight-second silent pattern with actual landscape/portrait/square bytes. Repeated JPEG frames and clock progress do not prove composition, captions, audio, model execution, production agreement or restart-safe jobs.

### Recorded presentation and observed diagnostics

Optional producer-recorded `agentHistory` restores actual status/action/message/error presentation on initial and authoritative reads. It never replays project operations, writes, notifications, cuts or missing action preimages. Exact legacy history without the capability stays unavailable. Synthetic history is process-local and does not establish production retention or interleaving with historical user messages.

Diagnostics are opt-in to separately approved identity-free collectors. No default endpoint, identity, autocapture, text, names or raw error messages are sent. First-op latency requires an observed same-tab prompt start and first authoritative agent op; gaps/restored snapshots/user/replayed ops do not create a timing. Warmup duration measures the observed ready-and-connected wait. Render completion duration measures only this visit's observed queued/rendering-to-done interval, not claimed backend total time. Already-finished restored jobs skip it. `render_started` follows successful approval, never navigation or uncertain acceptance. Direct PostHog/Sentry SDKs remain proposals under the no-extra-dependencies rule; the bounded adapters do not establish live provider or cloud-region acceptance.

### Synchronized cut comparison and guarded restore subset

Device-local cuts can be compared with the current edit using one controller, one absolute time sample, one Pixi Application and the shared total six-decoder budget. Current edit is left and historical cut is right, each fitted into its full viewport before a screen-space wipe. Historical audio is never routed. Pending resources, unavailable fonts and decoder pressure are explicit states, not successful first-frame claims. Poster capture is rejected while comparing. Comparison and detached previews are read-only across the built-in editing API and injected mutating command hooks; live authoritative updates continue behind the presentation.

Restoration uses existing typed edit operations, not an invented restore endpoint. The pure planner rejects unsupported marker/order changes, missing or changed referenced assets, locks, optional-field absence that cannot be represented reversibly, busy/draft/offline or non-durable editors. Exact forward, inverse and redo must preflight. Confirmation preserves the exact reviewed project/version, assets and operations in a persisted strict guard. Strict restores and their undo/redo do not take the ordinary rebase path or automatically retry a conflict; unknown acceptance remains unknown after reload. A matching cut is a no-op with no mutation/history. Universal cut restoration and real producer acceptance are not claimed.

Structural renderer/controller/editor and UI tests are not real GPU pixels, media/audio synchronization, screen-reader, device-performance or backend acceptance. The earlier hosted checkpoint had no usable GPU and did not test these newly added capabilities. A fresh bounded hosted checkpoint and production acceptance remain separate gates.
